# 党员发展计划辅助系统 · 项目计划

## 一、业务背景
- 网站类型：学校工具类网页，服务学生党员发展与辅导员管理。
- 用户规模：几百人，并发很低。
- 开发团队：2-3 人，Python 经验少、C++ 背景、无前端框架经验。
- 维护方：校学生会（非专业开发者，需低维护成本、标准化后台）。
- 部署：国内轻量云服务器，Ubuntu 24.04 LTS；上服务器前先在本机 Docker 试跑。
- 第三方集成：仅国产大模型 AI 接口（默认 DeepSeek API，兼容 OpenAI SDK 格式）。

## 二、技术架构（硬性约束）
1. 后端用 Python；Neo4j 描述《发展党员流程图》的结构关系；MySQL 存用户/事务数据；统一为 API 接前端。
2. 前端调用 impeccable 改善 UI，并遵循 `skill/frontend-design/` 审美规范，禁 AI 通用审美。
3. 数据库用 MySQL，结构精简，不写得很大。
4. 异步/定时任务 Celery + Redis；可用 Django management command + cron 替代处注明。
5. AI 封装于 `services/ai_client.py`，openai SDK 兼容 DeepSeek，Key 读环境变量，不硬编码。
6. 部署 Gunicorn + Nginx + systemd，提供部署脚本与命令清单。
7. 代码注释与 README 中文，面向新手维护者。

## 三、功能模块
### 模块一：材料与节点管家
- 数据模型覆盖《发展党员流程图》五阶段，每阶段关联必备材料模板。
- 学生注册后自动创建个人进度档案；档案页展示当前阶段、材料清单（已有/缺失）、截止时间节点。
- 定时任务扫描临近截止节点，生成站内通知（预留邮件接口），推送材料模板链接与撰写要点。
- 纯数据库查询实现清单梳理，不调用 AI。

### 模块二：智能材料质检员
- 支持上传 .docx，用 python-docx 解析文本与段落格式。
- 格式规范用规则引擎检查（字体、字号、标题居中、落款日期等），不消耗 AI。
- 易错点（逻辑矛盾、表述不规范）调用 AI 辅助提示，prompt 明确"只列问题、不改原文"，结果标注"AI 建议仅供参考"。
- 质检结果列表展示，区分"规则检查"与"AI 建议"两类。

### 模块三：个性化成长导师
- 对话页面：前端聊天框 + fetch，后端注入系统 prompt（学生阶段、专业、对话摘要）调用 AI。
- 对话历史存 `ChatMessage` 表（保留逐条历史，供上下文摘要与后台查看）。
- 辅导员可在后台选中学生触发"党课提醒"等节点通知。

### 模块四：辅导员工作台
- 优先复用 Django Admin（注册模型、list_display、list_filter、search_fields、自定义 admin action）。
- 权限用 Django Group：辅导员组仅能查看本院系学生（重写 get_queryset 过滤）。
- 提供材料完成率等只读统计字段。

## 四、脱敏红线（必守）
1. 知识库 / 示例 / 测试数据一律化名（如 张某、李某、王某）。
2. 材料模板中个人信息一律用 `{{占位符}}`（如 `{{姓名}}`、`{{学号}}`、`{{院系}}`、`{{日期}}`）。
3. 涉密材料（真实姓名、证件号、个人政审详情等）不入对话、不入代码。
4. 开发期间产生的截图、日志、导出文件不得包含真实个人信息。

## 五、阶段计划
1. 基线资产 + 技能 + 知识库 + Django 脚手架。
2. 数据模型 + Neo4j 图初始化 + 迁移。
3. 服务层（AI 客户端 / 规则引擎 / 质检编排）+ Celery 任务。
4. 四大模块视图 / URL / 模板 / Admin。
5. 前端设计（frontend-design + impeccable）。
6. 部署（Docker 本地 + Gunicorn/Nginx/systemd）+ README + WSL2 验证。
